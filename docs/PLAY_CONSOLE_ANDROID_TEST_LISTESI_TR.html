§0 — Başlamadan önce (kontrol)

  1. Play Console giriş play.google.com/console → FlyFam uygulamasını seç (paket adı: com.flyfam.app).
  2. Yetki Hesabında Release / Admin yetkisi olmalı (tester listesi + release yükleme).
  3. Google hesabı kuralı Play tester e-postaları Google hesabı olmalı. Gmail dışı adresler (Hotmail, kurumsal) yalnızca o e-posta bir Google hesabına bağlıysa çalışır.
Bu liste “uygulamada Android cihaz kaydı olan” kullanıcılar. Play’den indirip hiç push token kaydetmeyen kullanıcı burada olmayabilir. Listeyi yenilemek için aynı SQL/export adımını tekrar çalıştırın.

§2 — Play Console’da tester listesini oluştur

Öneri: önce Internal testing (hızlı, inceleme yok). Sonra Production.

  1. Menü Sol: Test and release → Testing → Internal testing (Test ve yayınlama → Test → Dahili test).
  2. Testers sekmesi Üstte Testers / Test kullanıcıları’na tıkla.
  3. E-posta listesi oluştur
    • Create email list / E-posta listesi oluştur
    • Liste adı: FlyFam Android users 2026-08
    • §1’deki e-postaları yapıştır (satır satır veya virgüllü)
    • Save changes
  4. Listeyi track’e bağla Internal testing → Testers → oluşturduğun listeyi seç → kaydet.
  5. Opt-in linkini kopyala Sayfada “How testers join your test” / “Test kullanıcıları nasıl katılır” altında Copy link. Bu linki ekibe WhatsApp/e-posta ile gönder.
Tester, linke tıklayıp Become a tester / Test kullanıcısı ol demeden Internal build’i Play’de göremez. Her kişi kendi Google hesabıyla opt-in yapmalı.

§3 — Yeni sürümü Internal testing’e yükle

  1. AAB hazır olsun versionCode Play’deki en yüksek değerden büyük olmalı (şu an projede 33 → yeni build en az 34).
  2. Yükle Internal testing → Create new release → AAB yükle → Release notes (TR/EN kısa) → Review release → Start rollout to Internal testing.
  3. Doğrulama checklist (tester)
    • Opt-in link → Become a tester
    • Play Store → FlyFam → Update / Install (Internal)
    • Manuel uçuş ekle (ör. PC*) → yerel saatin doğru olduğunu kontrol et
    • Roster’da saatlerin Z/+3 kayması olmadığını doğrula

§4 — Test ekibine katılma (kullanıcı tarafı)

  1. Telefonda Play’e giriş yapan Google hesabı = listede olan e-posta olmalı.
  2. Gönderdiğin opt-in linkini aç → Become a tester.
  3. Play Store’da FlyFam sayfasını aç (gerekirse “Internal testing” rozeti görünür).
  4. Update / Yükle → uygulamayı açıp kritik akışları dene.
Kapalı test (Closed testing) istersen aynı e-posta listesini Test and release → Testing → Closed testing track’ine de ekleyebilirsin. Closed track bazen küçük bir inceleme ister; Internal daha hızlıdır.

§5 — Production + “herkes güncellesin” (Play + uygulama)

  1. Production release Internal doğrulandıktan sonra aynı AAB’yi Test and release → Production’a yükle.
  2. Staged rollout (önerilir) Önce %20 → sorun yoksa %50 → %100. Play Console → Production release → Manage rollout.
  3. Önemli gerçek Play, cihazda yüklü eski sürümü otomatik “zorla” silmez. Production %100 olsa bile kullanıcı Play güncellemesini erteleyebilir.
  4. Gerçek zorunlu güncelleme Uygulama açılışında versionCode < min ise ekranı kilitle + “Play’den güncelle” butonu (Supabase config). Bu ayrı bir geliştirme adımıdır; Play ayarı tek başına yetmez.
Pratik sıra: Internal liste (§2) → Internal AAB (§3) → tester opt-in (§4) → Production staged (§5) → sonra (istersen) force-update kapısı.

§6 — Listeyi yenilemek (ileride)

Android kaydı değişince e-postaları tekrar çekmek için Supabase’te device_tokens.platform = 'android' kullanıcılarının auth.users.email değerlerini export et.
